01

The brief

Sage Sparrows runs marketing for D2C, real estate and EV brands with a team of about 15. The work was spread across Google Sheets and WhatsApp threads, and every brand's numbers sat in a different place: Meta, Google Ads, GA4, Shopify, Clarity.

With no in-house performance marketer, the agency needed one place to run its work and one dashboard every brand's ads could be run from. When a campaign stopped spending for days, nobody caught it. That was the kind of gap it had to close.

02

What I built

  • Tasks with a reviewer-driven stage flow: every task starts at Briefing, and after each review the reviewer picks the next stage, department and people. Work can be sent back, and Shipped (published) is separate from Done.
  • Google Calendar sync for work blocks and deadlines, and a scheduler that respects priority, deadlines and working hours.
  • Real-time chat: channels, DMs, threads, mentions, reactions, read receipts, file sharing and deep links to any message.
  • A KPI calculator with weighted department scoring, MD scores and profit sharing, with achievements computed automatically from platform data.
  • Data pipelines from Meta Ads, Google Ads, GA4, Shopify, Google Trends and Microsoft Clarity, synced daily, plus an ad engine that classifies every ad as TEST, KILL, OPTIMIZE, BREAKEVEN or SCALE.
  • Company mail, calendars and file storage on a self-hosted Stalwart server, used from inside the app.
  • Push notifications, 6-tier role-based access, Ctrl+K global search, notes with share links and a daily standup board.
  • A native SwiftUI Mac app with every page rebuilt, an encrypted local cache, and a system-wide command bar (Option+Space).
  • An MCP server so Claude can query the analytics directly.

03

How I built it

First flight on the hosting the agency already hadMarch 2026+

A Fastify and MySQL backend, a React and Tailwind web app, Google sign-in with MySQL-backed sessions, and WebSockets for chat and live updates. It runs on the agency's existing cPanel host, so it shipped without new infrastructure.

Fix what the team felt first, then make the numbers rightJune and July 2026+

Notifications and login refresh on iPhones and Macs came first. Then analytics became the top priority: I audited all 21 analytics pages, found 19 defects in 4 recurring classes (rates added together, snapshots summed across days, platforms storing the same metric differently, and dates bucketed in the wrong timezone), fixed every one, and folded the 21 pages into one dashboard. A Google Ads sync that had been dead for 13 months, because the API version it used was retired, came back with 25 new fields.

A native Mac app, built from scratchJuly 2026+

A webview wrapper was tried and thrown out in favour of real SwiftUI. Native sign-in uses an additive, per-device token that is hashed at rest and can be revoked, so the web's cookie flow stayed untouched. Every page was rebuilt natively, including all 16 analytics dashboards, then audited line by line against the web app.

Make it hard to breakJuly and August 2026+

The Mac app gained an encrypted SQLCipher cache, so a hosting hiccup shows slightly stale data instead of an error screen. GA4 turned out to be silently cutting every large report at 10,000 rows; the sync now pages through everything.

Talk to itSeptember 2026+

An assistant layer, now 49 actions. The model only names an action and quotes the words; code resolves them, checks permissions, asks for confirmation and executes, with real undo. An audit before release caught 27 of the then 47 tools calling their routes wrongly. Atlas 1.0, a model I fine-tuned, runs it on each person's Mac.

Keep it healthyOctober 2026+

A dependency security pass took every audit to zero, and abandoned carts from Shiprocket Checkout now land in Verte's and Alexandre Christie's sales sheets automatically.

Decision: native, not wrapped

Web push was unreliable on Macs and Google blocks sign-in inside embedded webviews. A native app holds the WebSocket and fires real system notifications. The server stays the single authority, so the planned Windows, iOS and Android clients inherit the same logic instead of re-implementing it.

Decision: Shopify decides revenue

Income always comes from Shopify, never an ad platform's attributed revenue, and traffic from GA4 and Clarity together. Anything a platform attributes to itself is labelled that way on screen.

Decision: glass on chrome, flat content

Translucency is used only for navigation and controls. Tables, charts and chat stay flat and high-contrast, because glass over dense data hurts legibility and slows down the machines the team actually uses.

The operations platform Sage Sparrows runs on. It replaced scattered Google Sheets and WhatsApp threads with one place for tasks, chat, KPIs and analytics across every brand the agency manages.

  • In daily use: on 2 Sep 2026 it held 9 brands, 56 campaigns, about 110 assets and 120 open tasks

  • Tasks with a reviewer-driven stage flow, real-time chat (threads, mentions, reactions, file sharing), Google Calendar sync and global search

  • Six-tier roles, TOTP-gated impersonation, web push with retries and batching, and a WebSocket build id that reloads clients after a deploy
  • Plain-English and voice commands across 49 actions, with an undo log and single-use plan tokens

One owned encryption format for company data across every SparrowOS client and the backend: a versioned envelope over standard AES-256-GCM.

  • Owns the format, key hierarchy and rotation, and never invents the cipher itself
  • A byte-for-byte spec that web, macOS, iOS, Android, Windows and the server can all implement
  • Zero dependencies on every platform: Node crypto, CryptoKit, javax.crypto, .NET and WebCrypto

The company's own workspace instead of a Google Workspace subscription: email, calendars and file storage self-hosted on Stalwart, with SparrowOS as the interface.

  • Runs the company's mail domain, and sends the storefront checkout alerts
  • Stalwart on the company VPS serving IMAP, SMTP, JMAP, CalDAV, CardDAV and WebDAV, so Apple Mail and phones sync natively
  • Web mail inside SparrowOS over JMAP, with attachments, snooze and shared team inboxes
  • Mailbox admin in SparrowOS: create and remove accounts with storage quotas, and manage shared inboxes
  • Sparrow Drive: each person's files on Stalwart over WebDAV, with share links minted by SparrowOS
  • DKIM-signed mail with SPF and DMARC, after finding the rotating-key trap that lets Gmail silently drop mail
  • Began as a small self-built Node SMTP service, replaced by Stalwart once a full workspace was in scope
